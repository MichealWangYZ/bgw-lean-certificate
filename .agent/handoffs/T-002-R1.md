## 3. The defect and its root cause

The first run of the exact command in the task failed:

```text
ValueError: fresh run differs from saved evidence: sigma_hp.log
```

`bgw/reproduce.py` was setting `OPENBLAS_NUM_THREADS=1` and `OMP_NUM_THREADS=1`.
The archived run did not. With one BLAS thread the EPM diagonalization selects a
different, equally valid eigenvector basis inside the degenerate subspaces, so
the run is *not* the same calculation as the archived one.

Isolation experiments (each in a throwaway `/tmp` directory, no repo writes):

1. `epm2bgw.x` on the archived `WFN.in`, 1 thread versus 2/4/8/16/default:
   `WFN` differs from the archived `WFN` in **21179 bytes** at 1 thread and in
   **5 bytes** at every count `>= 2` and at the host default. Two runs at the
   same thread count differ in **exactly 1 byte**.
2. Those 1-5 residual bytes are the run date and time embedded in the binary
   header (`WFN-Real  10-Sep-2026  23:25:23 -0500`). `WFN`, `WFNq`,
   `WFN_inner`, `RHO`, `VXC`, `eps0mat` and `epsmat` can therefore never be
   byte-identical across runs; only the text outputs are comparable, which is
   what the harness compares.
3. Rerunning the instrumented `sigma.real.x` on the **archived**
   `WFN_inner`/`eps0mat`/`epsmat`/`RHO`/`VXC` reproduced `sigma_hp.log`,
   `gpp_branch_counts.dat`, `gpp_kernel_dump.dat` and `gpp_nearpole_dump.dat`
   byte-for-byte. The GPP kernel is bit-reproducible on this host; the gauge
   freedom enters only through the mean-field and epsilon stages.

Fix: inherit the ambient threading (as the archived run did) and expose
`--blas-threads N` for deliberate experiments. This restores byte identity
without weakening any comparison. The harness still fails hard on any
difference; it now also says *what* differed.

Measured effect of the wrong threading, from the retained failure report
`artifacts/t002-claude-reproduction-1thread/report.json`:

* `sigma_hp.log`: 3 of 169 lines differ, lines 111-113 only. That is the
  second, symmetrized off-diagonal block. Example line 111, column `X`:
  saved `-15.811060321` versus `-15.810464596`.
* The diagonal quasiparticle table is unchanged, and **all 24 upstream
  assertions still pass** in the single-threaded run. The upstream suite does
  not detect this difference; only the byte comparison does.
* `gpp_kernel_dump.dat`: all 64 rows differ, worst relative deviation
  `3.00e-14` (`sch`); `gpp_nearpole_dump.dat`: all 32 rows, worst `2.50e-12`
  (`ieps`, the dielectric input itself). `gpp_branch_counts.dat` is unchanged,
  so no branch selection flipped.

  `evaluate_assertions(assertions, log_text)`, so the upstream parser is now

  contain no diagnosis.

  `GREP` takes the **first** matching line (`grep -A$off ... | awk NR==$off+1`,
  with an explicit comment to that effect) and that `Precision` stays in force
  until changed. The parser now documents and matches both.

## 8. Assumptions and limits that remain

1. **Not a clean build.** `/tmp/bgw/BerkeleyGW-4.0-reviewed-pristine` is an
   incremental pristine `Sigma` rebuild that reuses previously compiled
   real-flavor dependencies, as Codex stated. The reproduction certifies
   neither the compiler nor the libraries. Recorded in section 7.8 of the doc.
2. **Byte identity is host- and threading-specific**, not a portable property.
   It holds on this 16-core host at any BLAS thread count `>= 2`, including the
   default. A different machine or BLAS may legitimately fail the byte
   comparison while satisfying all 24 upstream assertions. Codex may prefer a
   documented numeric tolerance for the off-diagonal block instead; I did not
   introduce one, because that is a contract decision, not a repair.
3. **Threading is now inherited, so the harness is not hermetic.** The
   effective `OPENBLAS_NUM_THREADS`/`OMP_NUM_THREADS` are recorded in
   `report.json`. Pinning to a fixed count `>= 2` would be more hermetic but
   would encode a host-specific choice the archived run did not make.
4. Branch predicates in `bgw/verify_export.py` are evaluated over exact
   rationals, not IEEE binary64, so they are not threshold emulation. I
   re-derived the four constants from the source and they are correct:
   `limitone = 1/(TOL_Small*4) = 250000` and `limittwo = sig%gamma**2 = 0.25`
   (`Sigma/mtxel_cor.f90:1698-1699`), `TOL_Zero = 1e-12`
   (`Common/nrtype.f90:162`), `sig%sexcut = 4.0`, `sig%gamma = 0.5`
   (`Sigma/inread.f90:151-152`). The clamp predicate
   `abs(ssx) > sexcut*abs(I_eps) .and. wxt < 0` matches
   `Sigma/mtxel_cor.f90:1847-1848`.
5. The `occ != 1` reachability question from the T-002 handoff section 10 is
   still open and was not part of this job. No export record has `occ != 1`.
6. Unchanged trust boundaries: the Lean kernel checks the algebra; the Fortran
   transcription is human reading; the runs are experiments on one build, one
   material, one flavor, `occ = 1` only; the compiler, runtime, conda
   toolchain, and Python are untrusted.
