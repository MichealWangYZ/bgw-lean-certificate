Transcribes the kernel arithmetic and proves it coincides with S1. Namespace

`occupiedNearPole`, `emptyBranch`, `delwComment`.

| Theorem | Hypotheses | Statement |
| --- | --- | --- |
| `ch_term_eq` | `wt ≠ 0` | shared `0.5*sch` rewrite |
| `occupiedGeneric_eq_rawOccupied` | `wt ≠ 0` | generic branch = S1 `rawOccupied` at `A = Omega2` |
| `occupiedNearPole_eq_occupiedTerm` | `wt ≠ 0`, `x ≠ wt`, `x ≠ -wt` | near-pole branch = S1 `occupiedTerm` |
| `emptyBranch_eq_emptyTerm` | `wt ≠ 0` | unoccupied branch = S1 `emptyTerm` |
| `branches_agree` | `wt ≠ 0`, `x ≠ ±wt` | the source's own two branches agree |
| `tendsto_occupiedGeneric` | `wt ≠ 0` | near-pole branch is the limit of the generic one |
| `occupiedNearPole_limit_value` | `wt ≠ 0` | that limit is `Omega2/(4*wt^2)` |
| `delwComment_eq` | `wt ≠ 0`, `x ≠ wt` | comment's `delw` = `1/(2*delw_code)` |
| `commentFormula_eq_occupiedTerm` | `wt ≠ 0`, `x ≠ -wt` | the comment's formula still gives the merged value |
| `branch_mismatch` | `wt ≠ 0`, `x ≠ ±wt` | exact branch difference when `occ ≠ 1` |
| `branch_mismatch_zero_of_occ_one` | `wt ≠ 0`, `x ≠ ±wt` | that difference vanishes at `occ = 1` |

Two hypotheses are weaker than one might expect and this is deliberate:
`occupiedGeneric_eq_rawOccupied` and `emptyBranch_eq_emptyTerm` need only
`wt ≠ 0` because both sides use the *same* totalized division at `x = wt`.

## 7. Findings a reviewer should check independently

1. **The mapping is exact, not approximate.** With `A = Omega2 = wtilde^2*I_eps`,
   `x = wxt`, `w = wtilde`, and external factors divided out, the generic branch
   *is* S1 `rawOccupied` and the near-pole branch *is* S1 `occupiedTerm`. Our
   cancellation theorem is therefore the statement that BerkeleyGW's own two
   branches agree. This was not obvious before reading the source.

2. **Units were wrong in my first draft and are corrected.** The kernel works in
   **eV**, not Rydberg: `Sigma/input.f90:806` does `kp%el = kp%el*ryd` on read.
   So `wtilde`, `wxt`, `e_lk` are eV, `Omega2` is eV^2, and `ssx`/`sch` are
   dimensionless; `vcoul` (Ry) carries the dimension and `shiftenergy.f90:113`
   applies `ryd`. Confirmed against the export (`e_lk = -2.552134028802625`
   matches the eV `Emf` in `sigma_hp.log`; `wtilde = 17.168` eV is the Si
   plasmon). This makes `A` come out in eV^3 exactly as S2 requires.

3. **`sig%gamma` is 0.5 eV, so the merged branch covers `|x-w| <= 0.5` eV.**
   BerkeleyGW essentially never evaluates the raw split near the pole. Our S4
   catastrophic-cancellation figure is about the *unprotected* expression and
   must not be cited as a defect in BerkeleyGW. I recommend Codex add that
   sentence to `docs/DEMO_RESULTS.md`.

4. **The merged branch is common, not a corner case.** Counted over the whole
   Si run: generic 11,845,337; near-pole 80,163; dropped 94,888; `sexcut` clamp
   44,937.

5. **`occ != 1` breaks the cancellation, and this is a real limit of our spec.**
   The source applies `occ` to `ssx` but not to `sch`, so at `occ = 0.5`
   (Fermi level) or under `do_smearing` the two branches differ by
   `(1-occ)*[Omega2/(2w(x+w)) + Omega2/((x-w)(x+w))]`, which blows up at
   `x -> w`. Proved as `branch_mismatch`. **I am not claiming this is a bug in
   BerkeleyGW** --- it may be unreachable if `sig%tol` is always small enough
   that a half-occupied state never satisfies `wdiffr <= gamma^2`. I did not
   check that, and Codex should not assume it either way. Our export contains
   no `occ != 1` record.

6. **The source comment disagrees with the source code about `delw`.**
   Line 1777 documents `delw = (wx - wtilde)/(2*wtilde)`; line 1822 computes
   `delw = wtilde/(wx - wtilde)`. The documented quantity is `1/(2*delw_code)`.
   Both the comment's stated near-pole formula and the code's statement evaluate
   to the same merged value (`commentFormula_eq_occupiedTerm`), so this is a
   documentation defect, not a numerical one. Worth reporting upstream.

7. **`Sigma/wpeff.f90:16` says `wpmtx` is in eV^2, and that is correct** --- I
   initially assumed it was stale. It is the `wtilde ... Ry` assumption that was
   wrong.

## 8. Failed attempts, for whoever repeats this

* `sudo apt-get install gfortran` fails: password required, non-interactive
  session. Use the `/tmp/mm` micromamba route instead.
* `make -C Sigma sigma.real.x` **does not work** as an incremental rebuild: it
  loses the object list and fails at link with `undefined reference to 'main'`.
  Use `make -C Sigma` (default goal) from a tree that already built, or a full
  `make real`.
* `make all-flavors` leaves **complex-flavor** `.o` and `.mod` files in place.
  A subsequent real-flavor recompile of `mtxel_cor` then fails with
  `Type mismatch in argument 'wpmtx' ... passed REAL(8) to COMPLEX(8)`, because
  it picks up the complex `wpeff_m.mod`. Build `make real` only, from clean.
* The first `arch.mk` attempt failed on `Cannot open included file
  'fftw_f77.i'` (FFTW 2 API). Add `-DUSEFFTW3` to `MATHFLAG`.
* `WFN_co.in` writes a file named `WFN_inner`, not `WFN_co`; my first pipeline
  script died on `mv WFN_co WFN_inner`.
* My first export filtered on `n1true == 1`, which only ever caught the generic
  branch. Filtering on the near-pole branch itself is what produced the 32
  records that actually matter.
