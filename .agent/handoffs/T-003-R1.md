## 2. What was wrong and what changed

### F1 -- a successful exit did not enforce the record contract

Root cause: the only numeric gate was the `ssx_post` residual, and **12 of the
29 exported fields were parsed and then never read** (`wtilde2`, `omega2`,
`delw`, `delwr`, `wdiffr`, `den_generic`, `den_nearpole`, `den_merged`,
`e_lk`, `e_n1kq`, `efermi`, `occ_broadening`), while `REPORT.md` section 3
claimed the 48 records "all verify". That claim was wrong and is corrected.

The checker now splits its checks into three kinds that are never mixed:

1. **Exactly-determined fields** -- equality, no tolerance. `sch == 0.0`
   (branch 2 assigns the literal at `mtxel_cor.f90:1835`), `limittwo == 0.25`,
   `limitone == 250000.0`, `wtilde_im == 0`, `wtilde_re > 0`,
   `occ in {0.5, 1.0}`, the exported branch label, the `sexcut` clamp decision
   against its own predicate, and nonzero denominators both as recorded and as
   recomputed.
2. **Half-occupation input consistency** -- `occ == 0.5` now requires
   `abs(e_n1kq - efermi) < sig%tol = 1.3606e-5` eV (`mtxel_cor.f90:1399`,
   `inread.f90:130,501`). Observed on all 48 records: **exactly 0.0**.
3. **Rounded derived intermediates** -- measured relative-residual thresholds
   against the exact rational value, never exact-real equality. Table in
   section 4 below and in `REPORT.md` section 7.2.

Fields with no relation internal to a record are now listed in
`unmodeled_fields` in the JSON and reported as unverified rather than implied
checked: `vcoul`, `ieps` (indirect only), `e_lk`/`e_n1kq` individually,
`n1true`/`igp`/`ig`, and `occ_broadening`.

On `occ_broadening` specifically, as the authorization required: its recorded
value is `0.10000000149011612` on every record, which is the **float32 image of
0.1**, because `Sigma/inread.f90:135` writes `sig%occ_broadening=0.1` with no
kind suffix. It is the untouched stored default. `sig%do_smearing` is a
separate flag and is not exported, so a nonzero value here is **not** evidence
that smearing was active.

### F2 -- tally and sample integrity were not enforced

* Tally files are validated: exactly the four expected rows, no duplicate rows,
  no unknown rows, integer and **nonnegative** counts, `sexcut` not exceeding
  the evaluations in its column, and a nonzero total.
* Control contract: zero `occ != 1` events in every row. Probe contract:
  nonzero `occ != 1` near-pole count.
* **Cross-run invariant**: each row's column sum must be equal between control
  and probe, because the manual Fermi level changes only the occupation
  classification, not which `(ig,igp,n1,iw)` evaluations occur (`flag_occ` still
  admits bands 1-4; `nvband = 4`, `ncrit = 0` in both runs). Measured:
  `11,500,172 + 345,165 = 11,845,337`, `76,461 + 3,702 = 80,163`,
  `92,920 + 1,968 = 94,888`; total `12,020,388` in both runs. This is what
  catches a count tampered to a different *nonnegative* value, which a
  nonnegativity check alone would miss.
* Record integrity: ids must be `>= 1` and unique, and identical record content
  is rejected. Duplicates are rejected in subset mode too.
* **Mode separation**: the default is now full-fixture validation, requiring
  exactly `--expect-records` (48) records with ids `1..48`. `--subset` performs
  explicitly labelled subset analysis and reports `mode: "subset"` and
  `full_fixture_validated: false`. The output also reports
  `exported_records: 48` next to `counted_qualifying_events: 3702` so the 48
  records are never confused with the 3,702 counted events.

### F3 -- the invalid-mode policy was stated incorrectly

My source deduction S9 said the default maps invalid modes to `wtilde = 0` and
that invalid modes therefore never reach the near-pole branch. **Both halves
were wrong.** Every assignment traced: `Sigma/inread.f90:82` sets
`sig%invalid_gpp_mode = -1`; `Sigma/inread.f90:455-456` reads the optional
keyword; there is no other assignment. The dispatch at
`mtxel_cor.f90:779-793`:

| Policy | `wtilde` becomes | Near-pole reachable? |
| --- | --- | --- |
| `0` | `(0d0,0d0)` | **No** -- `delw = 0` exactly, so `delwr > TOL_Zero` fails. Generic or dropped depending on `wdiffr`, not on the policy. |
| `1` | `sqrt(COMPLEXIFY(wtilde2))`, purely imaginary | **No claim** -- outside the mapped real-mode scope. |
| `2` | `CMPLX(2d0*ryd, 0d0)` = `27.21138506` eV | **Yes**, algebraically: an ordinary positive real mode, reached when the complete predicate selects branch 2 (e.g. `abs(wxt - 27.21138506) <= 0.5` eV, `delwr > TOL_Zero`, excluding `wxt = wtilde` exactly where `delw` is singular). **Not an executed witness**: no run here sets this policy. |
| `3` and **`case default`, i.e. the default `-1`** | `CMPLX(1d0/TOL_ZERO, 0d0)` = `1e12` eV | **No, for ordinary `wxt`** -- an asymptotic statement, see below. |

For the default sentinel, with `abs(wxt)` of ordinary band magnitude (up to
~`1e3` eV, covering all evidence here), `wdiffr ~ 1e24 >> limittwo` and
`delwr -> 1 < limitone`, so the **generic** branch is taken and the mode
contributes `ssx -> 0`, `0.5*sch -> -0.5*ieps`, the static COHSEX value the
source comment names. This is explicitly an ordinary-energy asymptotic
statement, **not** a claim for every `wxt`: branch 2 would require
`wxt ~ 1e12` eV. So invalid modes under the default are neither zeroed nor
dropped -- they pass through the generic branch as a COHSEX term.

The blanket exclusion is removed. This correction does not touch the executed
witness (ordinary positive real modes, `wtilde2 > 0`) or the smearing exclusion.

### Also qualified, per the authorization

* **Exact-real prediction vs the decision the source made.** The checker
  recomputes the predicate over rationals built from already-rounded recorded
  inputs, while the Fortran compared its own binary64 `wdiffr`/`delwr`. It now
  classifies **both** ways and reports `exact_and_recorded_branch_agree`. They
  agree on all 48 records -- an observation about these records, not a
  guarantee.
* **Mathematical MP1 range vs its floating-point evaluation.** The extrema at
  `y = -+sqrt(3/2)` are properties of the real function; the quoted decimals are
  its binary64 evaluation, and `erf`/`exp` accuracy is libm-dependent. The
  qualitative conclusion is robust because the overshoot, `3.5e-2`, is fourteen
  orders of magnitude above double rounding. `REPORT.md` also now notes that
  this range is unreachable in the GPP path at all.

## 4. Measured residuals and the thresholds they justify

Measured on the 48 archived records. **Observed maxima are measurements, not
proved universal error bounds.** Limits carry deliberate headroom so the
checker is not a hair trigger.

| Field | Kind | Observed max | Limit | Headroom |
| --- | --- | --- | --- | --- |
| `wtilde2` | relative | 9.361e-17 | 1e-14 | ~107x |
| `omega2` | relative | 1.774e-16 | 1e-14 | ~56x |
| `delw` | relative | 2.074e-16 | 1e-14 | ~48x |
| `delwr` | relative | 4.469e-16 | 1e-14 | ~22x |
| `wdiffr` | relative | 8.427e-17 | 1e-14 | ~119x |
| `den_nearpole` | relative | 3.071e-16 | 1e-14 | ~33x |
| `den_merged` | relative | 1.598e-16 | 1e-14 | ~63x |
| `den_generic` | **scaled** by `wxt**2 + wtilde2` | 6.813e-17 | 1e-14 | ~147x |
| `ssx_pre` | relative | 2.743e-16 | 1e-14 | ~36x |
| `ssx_post` | absolute vs exact | 4.2435598287864196e-19 | **1e-10, unchanged** | -- |
| `wxt` vs `e_lk + sig%dw*(iw-2) - e_n1kq` | absolute | 4.441e-16 | 1e-12 | ~2250x |

**`den_generic` needed a different bound and this is the one substantive
numerical finding of the repair.** `wxt**2 - wtilde2` is a difference of nearly
equal quantities near the pole, so its plain relative residual reaches
**4.094e-13** -- about **2722 ulps** -- from cancellation alone, with nothing
wrong. A plain `1e-14` relative limit would have rejected every genuine record.
Bounded against the magnitude of its operands, `wxt**2 + wtilde2`, the residual
is sub-ulp at `6.813e-17`. Had I set thresholds by feel rather than measuring,
this is the field I would have gotten wrong.

The `ssx_post` gate is byte-for-byte the pre-repair one, as required, and its
observed value is unchanged.

`sig%dw` is **not** an exported field. The probe input does not set
`finite_difference_spacing`, so `sig%dw = 1.0` by `inread.f90:149`. That is an
assumption about the input, and the `wxt` check above is what tests it: the
recorded offsets are exactly `(iw-2)*1.0` for the observed `iw` in `{2, 3}`.
My first measurement of this field showed a `7.9e-2` relative residual because
I had omitted the `sig%dw*(iw-2)` term; that was my error, not the data's.

## 7. Failed attempts

* My first threshold pass used a plain relative residual for every derived
  field. `den_generic` failed at `4.094e-13` against a `1e-14` limit. Measuring
  before choosing, rather than after, is what caught it; the fix was a
  cancellation-aware bound, not a looser limit.
* My first `wxt` consistency relation was `e_lk - e_n1kq`, which gave a
  `7.9e-02` residual. Cause: records have `iw in {2, 3}` and I had dropped the
  `sig%dw*(iw-2)` term. With it, the residual is `4.441e-16`.
* The synthetic record helper in the tests had to be made self-consistent: the
  repaired checker correctly rejected the old helper, because its `e_lk`,
  `e_n1kq` and `wxt` did not satisfy the relation now enforced.
* One test assertion of mine searched for `"do NOT mean smearing is on"` while
  the string reads `"does NOT ..."`. Caught by the test run, fixed.

## 8. Remaining limitations

1. Unchanged physical caveats. The manual Fermi-level witness is
   charge-inconsistent and self-flagged by BerkeleyGW; it shows no guard
   prevents the combination, not that a physical calculation reaches it.
2. Thresholds are justified by measurement on 48 records from one run, one
   material, one compiler and one host. They are not error bounds.
3. `exact_and_recorded_branch_agree` holds on these 48 records only.
4. Case 2 of the invalid-mode policy is an algebraic possibility; no executed
   witness exists, and I did not create one (out of scope).
5. The `occ != 1` reachability question for a physically self-consistent
   metallic or band-touching system is still open, and still blocked on a
   real-flavor non-HDF5 metallic asset.
6. `U2` from T-003 is untouched: the matrix elements are still not exported, so
   nothing here says anything about a weighted or physical magnitude.
7. No BerkeleyGW run was performed for this repair, so this job adds no new
   reproduction evidence; it relies on the byte-identical reproduction Codex
   already performed.
