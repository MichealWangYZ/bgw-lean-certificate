## 2. The two errors, confirmed and corrected

Both were mine, both were confirmed by my own independent derivation before I
edited anything.

### Error 1: `ssx` does not tend to zero at the large sentinel

I treated `Omega2` as fixed while `wtilde -> infinity`. The kernel
**recomputes** it at `Sigma/mtxel_cor.f90:1810-1812`
(`Omega2 = wtilde2 * I_eps_array`), so it scales as `wtilde^2` and

```text
ssx    = w^2*ieps/(x^2 - w^2)  ->  -ieps      (not 0)
sch/2  = w*ieps/(2*(x - w))    ->  -ieps/2
local  = -occ*ssx + sch/2      ->  (occ - 1/2)*ieps
```

At Codex's point `w=1e12, x=10, ieps=-1/4, occ=1`: `ssx = +0.25`,
`sch/2 = +0.125`, local `= -0.125`. The pre-correction report implied the
CH-only value `+0.125`. The `sexcut` clamp does not suppress it: the predicate
is false there, since `|ssx| = 0.25` is not `> sexcut*|ieps| = 1` and
`wxt > 0`. The setup loop stores `I_eps_array` before the invalid-mode policy
runs and does not zero it when the sentinel is chosen, so `ieps` survives.

### Error 2: `|wxt - w| <= 0.5` is not necessary for the near-pole branch

Generic requires `wdiffr > limittwo` **and** `delwr < limitone`. With
`d = |wxt - w|`, `wdiffr = d^2` and `delwr = w^2/d^2`, so those two tests are
`d > gamma` and `d > |w|/sqrt(limitone)`. Since `sqrt(limitone) = 500` exactly
and `gamma = 0.5`:

```text
generic    <=>  d >  max(gamma, |w|/500)
near-pole  <=>  d <= max(gamma, |w|/500)   and   delwr > TOL_Zero
```

The crossover is at `|w| = gamma*sqrt(limitone) = 250` eV. For the sentinel
`w = 1e12` the window is `2e9` eV, so my stated `0.5` eV was wrong by nine
orders of magnitude. Codex's counterexample (`w=1e12`, `x=w+1e6`) selects
branch 2 at `d = 1e6`, with the first generic test passing and the `delwr` test
failing.

**The ordinary-energy conclusion survives**, and is preserved: for
`|wxt| <= ~1e3` eV, `d ~ 1e12 > 2e9`, so the generic branch is still taken.

### A third error in the same sentence, not in the review

My sentence also called the limit "the static COHSEX value the source comment
names". That identification is **false**. Stripping the same factor
`K = aqsntemp*MYCONJG(aqsmtemp)*vcoul` from both kernels, `sigma_cohsex`
accumulates `asxtemp_loc = -ieps` with `asxtemp += asxtemp_loc*occ*K` and
`achtemp_loc = 0.5*ieps` with `achtemp += achtemp_loc*K`, giving
`-(occ-1/2)*ieps` -- the **negative** of the sentinel limit, in both channels.
I removed the identification rather than restating it with a sign, kept only
the defensible part (the limit is frequency-independent, which is the sense in
which the report now says "static"), and recorded the sign relation as an open
question for external review rather than asserting anything about intent. I
flagged this to the user before starting, and the T-004 authorization covers it.
