# T-003 Handoff: nonbinary occupation and the GPP near-pole branch

## 1. Status

`ready_for_review`. Not accepted; Codex owns acceptance.

All six work items were addressed. The outcome is not a single one of the three
supported forms but a partition: the question splits into three mechanisms with
three different answers. One is reachable with an executed witness, one is
excluded by input validation, one is inconclusive with a precisely named
missing asset. No theorem, specification, tolerance, accepted export, or
supervisor file was changed.

Full analysis: `bgw/occupation_audit/REPORT.md`. Provenance:
`bgw/occupation_audit/PROVENANCE.txt`.

## 2. Answer

| Mechanism | Reachable in `sigma_gpp_cpu`? | Strength of basis |
| --- | --- | --- |
| `occ = 0.5` from Fermi-level proximity (`mtxel_cor.f90:1399-1403`) | **Yes** | executed: 3,702 near-pole events with `occ != 1`, 48 records verified |
| `occ` from MP1 smearing (`mtxel_cor.f90:1405-1411`) | **No** | excluded by `inread.f90:528-532`; observed `die()`, exit 134 |
| `occ = 0.5` with no manual Fermi level, from a self-consistent band structure | **Inconclusive** | one deterministic sub-case derived, not executed |

The near-pole branch is therefore reachable at `occ != 1`, but only through the
half-occupation test, and in my witness only via an explicitly set Fermi level
that BerkeleyGW's own diagnostics flag as charge-inconsistent.

## 6. Why there is no executed witness for the physical route

`testsuite/Na_smearing` was inspected before use, as instructed. Its assets are
present (`jdftx_Na.tar.xz`), but it is **not runnable here**:

* it calls `epsilon.cplx.x` and `sigma.cplx.x`, i.e. the **complex** flavor,
  which is not built and is outside the mapped scope anyway (complex `wtilde`);
* it needs HDF5 (`WFN.h5`, `eps0mat.h5`), and the accepted builds are
  configured without HDF5;
* its sigma inputs use full-frequency plus smearing, which section 4 of the
  report shows is disjoint from the GPP path under test.

I did not install a toolchain, enable HDF5, or build the complex flavor: that
is a long campaign, not this bounded job. The missing input is stated exactly:
**a real-flavor, non-HDF5 metallic or band-touching test asset**.

## 7. Failed attempts and dead ends

* `occ_broadening 5.0` was my first and preferred probe, because smearing is the
  physically intended mechanism and would also have exercised `occ > 1`. It was
  rejected outright by `inread.f90:528-532`. That rejection is now the strongest
  result in the job, but it was not the result I expected.
* My instrumentation first hit **Fortran format reversion**: the output list had
  23 reals under a `20(es24.17,1x)` format, so each record was split across two
  lines (48 records appeared as 96 lines, 26 + 3 fields). Adding `recl=8192`
  did **not** fix it; the fix was correcting the repeat count to 23. The checker
  now rejects wrong field counts with that explanation, and a test reproduces it
  (`ParserTests::test_wrong_field_count_is_rejected`). An earlier `awk` decode I
  ran against the wrapped file was misaligned and its field labels were wrong;
  it was discarded, not reported.
* My first guess that a zero mode falls to branch 3 was **wrong**, and my own
  test caught it: with `wtilde = 0` and large `wdiffr` the generic test passes
  and the branch returns `ssx = sch = 0` (S10). The test was corrected to assert
  the actual behaviour, and a second test covers the genuine branch-3 condition.
* Placing the Fermi level on the **valence maximum** (10.0358 eV) instead of
  band 1 would put `occ = 0.5` on a band that does not reach the near-pole
  branch in this system; band 1 was chosen precisely because the accepted T-002
  export shows it is the band that does.
* `/tmp/bgw/BerkeleyGW-4.0` was not used, per the task's warning. I confirmed
  its `Sigma/sigma.real.x` is still absent.

## 8. Assumptions and limits

1. One revision, one material, real flavor, CPU algorithm, `occ = 0.5` only.
   Nothing here covers complex modes, GPU paths, full frequency, or COHSEX.
2. The witness configuration is **source-consistent and executed but physically
   inconsistent**, and BerkeleyGW says so (E6). It demonstrates the absence of a
   guard, not the occurrence of the state in practice.
3. Upstream inputs were reused, not regenerated, so the T-002-R1 BLAS-threading
   sensitivity is not re-entered. Threading was inherited and recorded, not
   forced. Only `sigma.real.x` was rerun.
4. The instrumented tree reuses previously compiled real-flavor dependencies;
   this is not a clean-toolchain build, same qualification as T-002-R1.
5. Branch predicates in the checker are evaluated over exact rationals, not
   IEEE binary64, so they are not threshold emulation.
6. The exported record set is 48 of 3,702 qualifying evaluations, taken as the
   first 48 encountered, so it is not a random sample.
