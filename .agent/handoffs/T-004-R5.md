## 1. Item 1 -- stale JSON field references

`weighted_mismatch.py` `what` now reads `see per_call_group_l1_note and
cross_group_warning`. The saved artifact was regenerated.

The regression is deliberately **general**, not a fix for these two names:
`FieldReferenceIntegrityTests` in `tests/test_weighted_audit.py` walks every
string leaf of the emitted object, extracts snake_case field-shaped tokens, and
requires each to be either a key somewhere in that same object or a member of
an explicit `NOT_FIELDS` allowlist (Fortran symbols, source paths, run ids --
`branch_mismatch`, `sigma_gpp_cpu`, `mtxel_cor`, `fermi_level_absolute`, and so
on). It runs against both the fresh run and the committed artifact.

Why both: the task's point is exactly right that fresh-vs-saved equality could
not catch this, because both copies were wrong in the same way. That test
compares the two artifacts to each other and has no notion of what a valid
field name is. There is also a mutation test,
`test_the_detector_would_have_caught_the_r4_defect`, which reinserts the exact
shipped string and asserts the detector fails.

   while the comment said something else. The helper now strips comment markers

   pass asserted its expected occurrence count before applying, after R3 and R4
   each shipped an edit that silently failed to match.

   which this pass does not change. Caught by running discovery before

   owner gate line would have been wrong in the acceptance record.
