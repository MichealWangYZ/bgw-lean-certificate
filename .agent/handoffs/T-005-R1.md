## The two findings, and what was actually measured

### Finding 1 — the clamp was never exercised

Confirmed. In the original table all 108 `SWEEP` rows had `wxt >= 0`, and
`mtxel_cor.f90:1848` needs `wxt < 0` as well as `|ssx| > sig%sexcut*|I_eps|`,
so `ssx_pre == ssx` everywhere and no observation of the clamp existed.

Repaired by adding boundary case **`C-`**: `I_eps = 1`, `wtilde = 0.26`, the
negative `|d| = gamma` surface near `wxt ~ -0.24`. This is a source-valid
positive real mode: `wtilde2 = 0.0676`, four orders above `TOL_Small`, so
`mtxel_cor.f90:774` does not cycle it and line 793 produces it as
`sqrt(wtilde2)`. The surface was located by the same bit-pattern bisection
(51 steps, adjacent representable pair), not hard-coded; the bisector was
generalised to bisect on `|wxt|` at fixed sign so it works below zero.

Measured, not assumed: at `|wxt| ~ wtilde` the denominator `wxt^2 - wtilde2`
is `~ -0.01`, so both candidates reach `|ssx| ~ 6.5` against a cutoff of
`4*|I_eps| = 4`. The clamp fires on **32 of the 36 `C-` rows**, including all
six representable neighbours of the surface at both occupations, and switches
off at the `+-1e-1` offsets where `|ssx|` drops below the cutoff. The four
unclamped `C-` rows are kept and tested as such.

### Finding 2 — the branch-3 claim omitted the invalid-mode path

Confirmed, and the original claim was wrong. `mtxel_cor.f90:774` reads
`if (abs(wtilde2) .lt. TOL_Small) cycle`: the filter is on the **absolute
value**, so a sufficiently negative `wtilde2` passes it. Lines 778-794 then
dispatch on `sig%invalid_gpp_mode`, and case `0` ("skip invalid GPP mode")
assigns `wtilde = (0d0,0d0)` at line 782. Branch 3 is therefore reachable in
source; it is a policy path, not an impossible state.

The corrected claim is split in two and both halves are now stated in the
source's own quantities:

* **No surviving positive-real mode can reach branch 3.** Branch 3 needs
  `wdiffr <= limittwo` and `delwr <= TOL_Zero`, i.e. `|wdiff| <= gamma = 0.5`
  and `wtilde <= sqrt(TOL_Zero)*|wdiff| <= 5e-7`, at the same time. Line 774
  keeps a mode only if `|wtilde2| >= TOL_Small`; if `wtilde2 > 0` then line 793
  gives `wtilde = sqrt(wtilde2) >= 1e-3`. The bounds are a factor 2000 apart,
  so the conjunction is unsatisfiable. The `minmode` row is the extremal
  witness — smallest surviving positive-real mode, at the `wxt` that maximises
  `|wdiff|` subject to the first conjunct being false — and it lands in
  branch 2 with `delwr = 4.0e-6`, six orders above `TOL_Zero`.
* **`invalid_gpp_mode = 0` supplies a zero mode from an invalid input**, which
  reaches branch 3 when `|wxt| <= gamma`, contributing exactly zero. Zero
  contribution is what "skip this mode" means; it is not evidence that the
  state is unreachable.

The zero-mode row is retained, relabelled `policy0`, and is now explicitly a
policy-path diagnostic. Because branch 3 can only be reached with `wtilde = 0`,
`Omega2 = 0` too, so the `BRANCH3` rows are reported as branch/ssx/sch
diagnostics rather than as a candidate comparison.

## Numerical findings, item 3 of the brief

Sign convention unchanged: `Delta = generic candidate - near-pole candidate`.

**At `occ = 1` the clamp creates a finite jump.** Across the `C-` surface, one
ULP of `wxt`:

| quantity | value |
| --- | --- |
| pre-clamp jump | `2.31e-14` on a local scale of `6.500` (3.6e-15 relative) |
| post-clamp jump | `-0.260` on a local scale of `0.260` |
| `ssx_pre` / `ssx` on the false side | `-6.500` / `0` |
| `ssx_pre` / `ssx` on the true side | `-6.760` / `0` |
| `sch`, false side (branch 2) | `0` by construction |
| `sch`, true side (branch 1) | `-0.520` |

The unclamped algebra is continuous here, exactly as at the `A`/`B` surfaces.
The clamp zeroes SX on **both** sides, but only the generic branch has a
nonzero CH, so the local value steps from `0` to `0.5*sch = -0.260` between
two adjacent representable `wxt`. This is the finite jump at full occupation
that the brief anticipated. It is preserved and quantified; no case or
tolerance was adjusted to recover continuity.

**At `occ = 0.5` the post-clamp jump is the same `-0.260`.** With `ssx = 0` on
both sides the occupation factor multiplies nothing, so the post-clamp
discrepancy is occupation-*independent* and is not proportional to `1 - occ`.
The `branch_mismatch` closed form gives `-0.130` at these inputs; it matches
the **pre-clamp** discrepancy to `1.20e-14` and is not a prediction for the
post-clamp result. The analyzer marks both `C-` crossings
`closed_form_applies = false` and returns `signed_jump_minus_predicted = null`
for them; the comparison is made only against the pre-clamp values, and a test
asserts that the post-clamp jump is *not* the closed form. The Lean theorem is
unchanged and was used only as a comparison target for the unclamped algebra.

**Unclamped cases are unaffected.** `A+`, `A-`, `B+` have `min(wxt)` of
`1.4`, `0.4` and `300.5`; zero clamped rows of any kind; and the T-005
continuity, half-occupation, linearity and invariance results stand as
reported there.

## Claim boundaries

- Still a standalone driver executing a source-faithful extraction. **Not a
  BerkeleyGW run**, no production-material impact, no self-energy error.
- The `C-` full-occupation jump is an observation about this driver's local
  accumulator at inputs we chose. It says nothing about whether those inputs
  occur in a real calculation, or with what weight. `wtilde = 0.26` and
  `wxt = -0.24` are numerical constructions selected to put the clamp and the
  branch surface in the same place, not a physical configuration.
- The clamp is deliberate source behaviour (`gpp_sexcutoff`), not a bug found
  here. What is reported is that it is discontinuous across a branch surface
  at full occupation, and that its post-clamp discrepancy is not what
  `branch_mismatch` describes.
- `branch_mismatch` is compared against the unclamped algebra only. It is a
  binary64 comparison against a real-number theorem, not a verification of
  either.
- The branch-3 argument is a hand argument about the source inequalities,
  supported by an extremal witness row; it is not a machine-checked proof of
  unreachability over all inputs.
- The hand transcription remains a human reading of the source; the digest
  constrains which bytes were read, not that they were read correctly.

## Failed attempts and corrections during the work

- First choice of `C-` brackets went through the existing bisector, which
  transferred the bit pattern of a signed value; for negative `wxt` IEEE bit
  order reverses. Fixed by bisecting on `|wxt|` at fixed sign, with a guard
  that both brackets are finite and of the same sign. The three positive cases
  are bit-identical before and after.
- The first analyzer version reported `jump_over_within_branch = Infinity` for
  `C-`, because inside a fully clamped branch every adjacent step is exactly
  zero. That is a fact about the clamp, not an unbounded ratio, and `Infinity`
  is not standard JSON; these now report `null`.
- I looked for a clamp-active boundary point where the two candidates clamp
  differently, which would have given a richer comparison. At this surface both
  exceed the cutoff (`6.76` and `6.50` against `4`), so both are zeroed. I did
  not move the case to manufacture the other outcome; the measured behaviour is
  what is reported.
