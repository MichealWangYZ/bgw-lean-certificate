## Question and Motivation

T-002 proved an exact-real mismatch between the two occupied branch formulas
when the occupation factor is not one. It did NOT establish that a consistent
BerkeleyGW execution can reach the relevant branch with such an occupation.
Resolve that source-level reachability question before proposing a larger
physical model. This is a bounded audit, not a request to fix BerkeleyGW.

## Work

1. Trace the definitions and actual constraints on `flag_occ`, `occ`,
   `e_n1kq`, `efermi`, `sig%tol`, `ncrit`, `do_smearing`, the evaluation energy,
   `wxt`, `wtilde`, and `gamma` in the pinned BerkeleyGW 4.0 source. Follow the
   necessary callers/input setup; do not assume they are independent inputs.
   Treat Fermi-level half occupation and smearing as separate cases. Derive
   the smearing occupation range; do not assume every value lies in [0,1].
2. Analyze the COMPLETE occupied near-pole predicate: the generic test fails,
   then `delwr > TOL_Zero`. Failure is not equivalent just to
   `wdiffr <= gamma^2`; the `limitone` condition matters too. Track setup skips,
   zero/imaginary modes, the energy clamp, and the subsequent `sexcut` clamp.
3. Give one of three supported outcomes: a source-consistent reachable witness;
   an exclusion argument with explicit hypotheses for a specified configuration;
   or an inconclusive result with precisely identified missing constraints.
   A finite search without a witness is not a proof of unreachability. An
   arbitrary tuple of independent numbers is not a reachable program state.
4. Prefer a tiny genuine run if existing inputs/builds make it practical.
   Inspect the shipped Na_smearing test before assuming its assets are present.
   A source-state witness is useful but must be labeled separately from an
   executed end-to-end witness. Do not launch a large materials calculation.
5. For an executed witness, retain inputs, source/patch hashes, commands,
   build/threading metadata, and enough precision to recover binary64 values.
   Export actual branch identity, occupation, pole real/imaginary parts,
   energy variables, branch thresholds, and pre/post-clamp SX/CH values.
   Distinguish a nonzero local expression from a nonzero weighted contribution.
   Check zero denominators and finiteness explicitly. Do not label a NaN an
   accepted scalar-model value.
6. Compare the two exact-real expressions on the SAME exported binary64 inputs,
   using the existing `branch_mismatch` formula without changing it. Distinguish
   mathematical mismatch, floating-point residual, and the source's intended
   physical approximation. A reachable mismatch alone is not a bug diagnosis.
