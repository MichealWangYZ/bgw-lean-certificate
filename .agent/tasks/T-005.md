## Scientific question

Test the actual binary64 arithmetic and complete branch predicate transcribed
from BerkeleyGW 4.0 `sigma_gpp_cpu` around the predicate boundary, then test the
partial-occupation mismatch law against the source-level arithmetic.

This must remain carefully named: a standalone real-flavor Fortran harness
executing a source-faithful extraction of the kernel statements is not a full
BerkeleyGW run and does not establish production-material impact.

## Required experiment

1. Add a small standalone Fortran driver under `bgw/branch_boundary/`. Preserve
   the relevant declared kinds, evaluation order, comparisons, default
   `TOL_Small`, `TOL_Zero`, `gpp_broadening`, `gpp_sexcutoff`, `Omega2`, `ssx`,
   `sch`, and sexcut logic from the pristine BerkeleyGW source. Clearly mark
   copied statements and record the pristine file digest and exact source
   lines. Do not modify any BerkeleyGW tree.

2. At fixed positive real `w` and nonsingular inputs, sweep `d = x-w` across
   both exact branch surfaces of the complete predicate. For the default
   `gamma=0.5`, include the binary64 neighbors immediately below, at, and above
   `|d|=0.5`, plus several wider offsets. Also exercise the `delwr` conjunct if
   it creates a distinct surface for the chosen parameters. Do not describe a
   decimal approximation as the exact machine boundary; use Fortran `nearest`
   or equivalent binary64 construction for ULP neighbors.

3. For every point record inputs, `wdiffr`, `delwr`, both predicate conjuncts,
   selected branch, pre- and post-sexcut `ssx`, `sch`, and the accumulated local
   value `-occ*ssx + 0.5*sch`. Compute the generic and near-pole candidates at
   the same inputs as explicitly counterfactual diagnostics, while keeping the
   selected result separate.

4. Run the sweep at `occ=1` and `occ=0.5`. At full occupation, quantify the
   jump between adjacent representable points straddling each branch surface
   and compare it with ordinary within-branch numerical variation. At half
   occupation, show the predicted branch discrepancy and its sign. Do not call
   either observation a material self-energy error.

5. At several fixed nonsingular points away from overflow and the sexcut clamp,
   evaluate `occ = 1, 0.75, 0.5, 0.25`. Define the branch discrepancy with an
   explicit sign convention and verify that `Delta(occ)/(1-occ)` is constant to
   a justified binary64 tolerance for `occ != 1`; verify `Delta(1)` is near
   zero. Compare against the closed form of
   `GW.GPP.BGW4.branch_mismatch`, without changing that theorem.

6. If cheap once the harness exists, add two invariant checks from the review:
   common energy-zero shifts preserve results because only `x=E-eps` enters;
   scaling and sign-flipping `I_eps` scales/sign-flips both candidate values and
   their discrepancy. Treat these as secondary; do not sacrifice items 1-5.
